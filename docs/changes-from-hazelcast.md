# Changes from Hazelcast 5.7.0

Hecaton was forked once from Hazelcast CE 5.7.0 and is maintained independently (spec §9,
D10). This file lists what differs from Hazelcast 5.7.0 beyond the mechanical rename in
[`tools/rebrand/rename-table.yaml`](../tools/rebrand/rename-table.yaml) (spec §5): first
what migrating applications notice, then a log of the changes made to inherited files while
creating the fork.

Add an entry in the same PR as any change that applications migrating from Hazelcast 5.7
can observe (API, config, wire, REST, metrics, file names, behaviour).

## Differences visible to applications

| Area | Hazelcast 5.7 | Hecaton | Since |
|---|---|---|---|
| Cloud-provider discovery (D9) | `aws`, `azure`, `gcp`, `eureka` join/discovery config (also in WAN batch publishers); client `hazelcast-cloud` and the `hazelcast.client.cloud.discovery.token` property; `AwsConfig`, `GcpConfig`, `AzureConfig`, `EurekaConfig`, `ClientCloudConfig` and their getters/setters | Removed; Kubernetes, TCP/IP, multicast and the Discovery SPI remain. XML/YAML/Spring configs and the client property fail with "Cloud-provider discovery is not supported in Hecaton; use tcp-ip, multicast, kubernetes or a Discovery SPI implementation". Official clients that add a WAN config dynamically still work; an enabled cloud section in it is rejected. | 0.1.0 |
| Spring XML namespace | `http(s)://www.hazelcast.com/schema/spring` | `http(s)://hecaton.org.uk/schema/spring` (both schemes resolve) | 0.1.0 |
| Jet connectors | Kinesis, S3, and the S3/GCS/Azure file systems | Removed (D9) | 0.1.0 |
| External integrations | `hazelcast-hibernate53`, `hazelcast-wm` (separate Hazelcast projects) | Not available; they are built against `com.hazelcast` | 0.1.0 |
| REST paths | `/hazelcast/rest/...`, `/hazelcast/health/...` | `/hecaton/...`; the `/hazelcast/...` paths are still served as aliases | 0.1.0 |
| SQL catalog name | `hazelcast` | `hecaton` (only fully qualified names `hazelcast.public.x` change) | 0.1.0 |
| Spring Boot | Spring Boot's built-in Hazelcast auto-configuration creates the instance (`spring.hazelcast.config`) | Spring Boot's built-in support only knows `com.hazelcast`. Add `hecaton-spring-boot3` or `hecaton-spring-boot4`, whose `HecatonAutoConfiguration` does the same from a `Config`/`ClientConfig` bean, `spring.hecaton.config` or a default `hecaton.xml`/`hecaton-client.xml` (YAML too) | 0.1.0 |
| Member protocol | Members open connections with `HZC` | `HCC`. A Hazelcast member cannot join a Hecaton cluster: its connections are closed and the Hecaton member logs a warning. Clients are not affected (`CP2` is unchanged) | 0.1.0 |
| Usage reporting ("phone home") | Members send usage statistics to `phonehome.hazelcast.com` once a day and probe cloud metadata endpoints to detect the environment; `hazelcast.phone.home.enabled` / `HZ_PHONE_HOME_ENABLED` turn it off | Removed: members send nothing anywhere. `hecaton.phone.home.enabled` is ignored | 0.1.0 |
| Enterprise-only features | Configuring an Enterprise feature on the open-source edition fails with "... requires Hazelcast Enterprise Edition" (or a similar message) | The same configurations fail until Hecaton implements the feature, with a message naming the feature and the milestone that delivers it, for example "TLS/SSL (F1) is not available in Hecaton yet; it is planned for milestone M3 (see the implementation plan)." Features Hecaton will not provide say what to use instead (symmetric encryption: TLS) | 0.2.0 |
| License key | `license-key` / `HZ_LICENSEKEY` enable Enterprise features; setting one through REST or Management Center installs it | Hecaton needs no license. A configured key is ignored with an INFO message and REST `POST /hecaton/rest/license` answers success with that message | 0.2.0 |
| TLS/SSL | Enterprise only | Available (F1) for member, client, WAN, REST and Memcache connections, unisocket or per advanced-network endpoint; `BasicSSLContextFactory` with the documented properties (see [`ee-class-map.md`](ee-class-map.md)); custom `SSLContextFactory`/`SSLEngineFactory` implementations work as before. A member with TLS enabled must have a key store. Unless `ciphersuites` is set, CBC cipher suites are not enabled; client-initiated TLS 1.2 renegotiation is refused | 0.3.0 |
| Security (authentication, client permissions) | Enterprise only | Available (F2, F3): realms with simple (users and roles), TLS client certificate, JAAS (custom login modules) or default authentication; member identities checked on join; client permissions for all permission types with principal, endpoint and deny rules, changeable at runtime; security interceptors. LDAP and Kerberos realms since 0.9.0. Security only applies to client operations: code running on members is not checked | 0.3.0 |
| Client failover (blue/green) | `HazelcastClient.newHazelcastFailoverClient` is refused by open-source members ("Cluster does not support failover") | Members accept failover clients: the client moves to the next cluster when its cluster goes down or blocks it | 0.2.0 |
| Member Java version | Members run on Java 17+ | Members need Java 25+ and fail at start otherwise ("Hecaton members require Java 25+; the client library supports Java 17+"); the client still runs on Java 17+. The start scripts also pass `--enable-native-access=ALL-UNNAMED` | 0.2.0 |
| WAN replication | Enterprise only | Available (F13) for IMap and ICache: batch publisher with static or discovered target endpoints, both acknowledge types, queue-full behaviours, backups of the WAN queues, active/active, WAN endpoints of the advanced network, management through the API, REST and Management Center. Clusters replicate only to Hecaton clusters (the protocol between clusters is Hecaton's). see [`wan.md`](wan.md) | 0.7.0 |
| Audit log, socket interceptor | Enterprise only | Available (F4, F5): the audit log writes to the logger `hecaton.auditlog` by default; see [`security.md`](security.md) | 0.9.0 |
| WAN sync and consistency check | Enterprise only | Available (F13): full and Merkle tree sync of maps, consistency check; see [`wan.md`](wan.md) | 0.9.0 |
| CP Subsystem persistence | Enterprise only | Available (F9): CP members restore their CP identity and CP group state on restart, also at another address; see [`cp.md`](cp.md) | 0.9.0 |
| User Code Namespaces | Enterprise only (enabling them fails on the open-source edition) | Available (F17); see [`user-code-namespaces.md`](user-code-namespaces.md) | 0.9.0 |
| Dynamic configuration persistence, configuration reload/update | Enterprise only | Available (F16); see [`dynamic-configuration.md`](dynamic-configuration.md) | 0.9.0 |
| Maven coordinates | `com.hazelcast:hazelcast` for members and clients | `uk.org.hecaton:hecaton` (core), `hecaton-client` (client applications), `hecaton-member` (member with all member modules) | 0.2.0 |
